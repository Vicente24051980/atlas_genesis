## Recovery policy

Newly recovered historical information should be appended as additional dated files or incorporated into a structured historical document with explicit `SUPERSEDED`, `HISTORICAL`, `CURRENT`, `PENDING`, or `UNVERIFIED` state markers.

Never rewrite history to make old snapshots look like the current canon.

## Completion criterion

The project is not considered fully recovered merely because a summary exists. Full recovery means every source segment that can be obtained from the months-long conversation history has been ingested into GitHub and classified into historical vs canonical layers without losing corrections, rejected hypotheses, algorithm iterations, portfolio snapshots, watchlist changes, Digital Twin readings or engineering decisions.
