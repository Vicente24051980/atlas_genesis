# DUAL PERSISTENCE LAW Ω — GitHub + Notion

Status: **INVIOLABLE CANONICAL LAW**  
Effective: **2026-08-12**

## Law

Every material ATLAS Ω information item, evidence record, research finding, market/news input, decision, rule, engine, algorithm, universe change, portfolio/watchlist change, thesis update, health update, architecture change, workflow change, implementation, audit, correction or canonical amendment MUST be persisted in **both GitHub and Notion**.

**GitHub + Notion is mandatory dual persistence.**

A change or material information item written only in chat or to only one persistence layer is not considered completed or fully recorded.

## Required state machine

- `PENDING` — requested or received but not written.
- `GITHUB_ONLY` — written to GitHub, Notion missing.
- `NOTION_ONLY` — written to Notion, GitHub missing.
- `PERSISTENCE_INCOMPLETE` — any one-sided or chat-only state.
- `DUAL_PERSISTED` — GitHub and Notion both updated and verified.

Only `DUAL_PERSISTED` counts as completed persistence.

## Mandatory execution rule

For every material ATLAS input or change:

1. Validate/classify it under Evidence Integrity Ω when applicable.
2. Persist the technical/versioned record in GitHub.
3. Mirror the operational/documentary record in Notion.
4. Keep both layers semantically aligned.
5. If either write fails, report `PERSISTENCE_INCOMPLETE` and identify the missing layer.

## Responsibilities of each layer

### GitHub

Canonical technical/versioned source for:
- code and algorithms;
- immutable or versioned rules;
- CURRENT_CANON documents;
- evidence/research logs that need auditable history;
- schemas, tests, APIs and runtime implementation;
- portfolio/watchlist and universe snapshots where versioning matters;
- auditable history and commit trace.

### Notion

Canonical visual/relational knowledge layer for:
- human-readable canon summaries;
- information/research mirrors;
- connected system architecture;
- current portfolio/universe views;
- rules, rationale and operational status;
- health and personal-tracking summaries stored within ATLAS;
- links back to GitHub source when applicable.

## Inviolable rules

1. No assistant may claim **implemented**, **saved**, **canonical**, **recorded**, **done**, or equivalent if only one persistence layer was updated.
2. No material ATLAS information may remain chat-only by default.
3. If one connector/write fails, report `PERSISTENCE_INCOMPLETE` explicitly and identify which side failed.
4. Do not silently defer the missing side to a later turn.
5. GitHub code/version history remains authoritative for technical implementation; Notion remains the visual/relational mirror. Dual persistence does not erase source-of-truth distinctions.
6. Contradictions between GitHub and Notion trigger an immediate reconciliation audit; they must not be resolved by silently choosing the more convenient copy.
7. Historical material need not be retroactively duplicated unless it is promoted, reused or modified as current canon.
8. User instructions explicitly saying not to touch one layer override execution for that turn, but the state must be marked `PERSISTENCE_INCOMPLETE` until dual persistence is restored.
9. Only an explicit later instruction from Vicente may amend or suspend this law.

## Completion check

Before declaring completion, verify:

`GitHub write successful AND Notion write successful => DUAL_PERSISTED`

Anything else:

`=> PERSISTENCE_INCOMPLETE`

## Scope

This law applies across ATLAS OS and all branches, including Atlas Financiero Ω, Salud, Gemelo Digital, Biblioteca, IA/Tecnología, Proyectos, Economía/Geopolítica, Psicológico, Conspiraciones Atlas and future branches.

## Integrity statement

**INFORMATION OR CHANGE NOT PRESENT IN BOTH GITHUB AND NOTION = NOT FULLY PERSISTED.**
